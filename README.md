# שיעור אלתור

המחברת של המורה: חלוקה להרכבים, משמעת וציון, תיעוד שיעורים עם בנקי תוכן,
וסרטוני תרגילים — לכל קבוצה שמלמדים, לא רק לכיתה אחת.

בנויה קודם כול לאייפון, לשימוש תוך כדי שיעור. עברית, RTL.

## המושגים

- **פרויקט** — קבוצה שמלמדים: כיתה, סדנה, הרכב, קורס. יש לו **סוג**, והוא
  **פעיל או לא פעיל** ("יא 26-27" נסגרת, "יא 27-28" נפתחת; ההיסטוריה נשמרת).
- **סוג פרויקט** — נתון, לא קוד. קובע אילו **יכולות** פעילות כברירת מחדל,
  האם יש **שכבה**, ואילו מאפיינים נוספים יש לקבוצה. מוסיפים סוגים מההגדרות.
- **יכולות** — הרכבים · משמעת וציון · תיעוד · סרטונים. לכל פרויקט אפשר
  לדרוס את ברירת המחדל של הסוג.
- **שיעור** — אחד לפרויקט ולתאריך. מחזיק את המשמעת, התיעוד, החלוקה והסרטונים.
- **בנקים** — רפרטואר, תרגילים ושיעורי בית. משותפים לכל הפרויקטים ומתמלאים
  מעצמם מהתיעוד.

## מה היא עושה

**הרכבים.** חלוקה אקראית־מכוונת ששומרת על הוגנות לאורך זמן: כל חלוקה נשמרת
(ההרכבים עצמם, לא רק ספירה), והחלוקות הבאות מתאזנות לפיה — מי שניגן פחות
מקבל עדיפות, וצירופים שעוד לא היו מועדפים. מצבים כפויים נלקחים בחשבון
(בסיסט יחיד מנגן בכל ההרכבים). החוקים ניתנים לעריכה לכל פרויקט: אילו תפקידים
חובה, גודל הרכב, כמה הרכבים לתלמיד — כך יוצרים גם הרכבים מיוחדים. **תלמיד
מוביל**: מוביל לכל הרכב, ואף אחד לא מוביל שוב לפני שכולם הובילו. איחור,
יציאה ועריכה ידנית מעדכנים את החלוקה הקיימת בלי לפרק אותה.

**משמעת.** לחיצה = חסר, עוד לחיצה = הגיע באיחור, שלישית = נוכח. מצב נפרד
לאי־הכנת שיעורי בית ולסימון "מוצדק" (גם בדיעבד, מתוך המעקב). טבלה מצטברת
עם ציון — 100 פחות 5 לחיסור, 3 לאיחור, 5 לש.ב.; מוצדק אינו מוריד; הערכים
ניתנים להגדרה — שאפשר להעתיק למערכת בית הספר, לכל השנה או לתקופה.

**תיעוד.** רפרטואר / תרגיל / ש.ב. כשדות חכמים עם הצעות מכל מה שנכתב אי־פעם,
ותיאור חופשי. הכול נשמר במסד; מסמך Google Docs לכל פרויקט נכתב ממנו מעצמו.

**סרטונים.** העלאה ישירה מהטלפון לתיקיית הפרויקט ב-Drive (לא דרך השרת, ולכן
בלי מגבלת גודל), בשם עקבי `תאריך · פרויקט · כותרת`, עם קישור לשיעור ולתרגיל.

## ארכיטקטורה

```
דפדפן (React + Vite, PWA)
  ├─ src/engine/   לוגיקה טהורה: חלוקה, ציון, תוכן המסמך. נבדקת ב-vitest.
  ├─ src/data/     Supabase, המאגר המקומי ותור הכתיבה, Google Drive/Docs.
  └─ src/screens/  המסכים. src/components/ רכיבים משותפים.
Supabase (Postgres + Auth)   מקור האמת. RLS: רק מייל שברשימת owners.
Google Drive / Docs          מסמכי התיעוד והסרטונים. הרשאת drive.file בלבד.
Vercel                       אירוח סטטי, נבנה מ-main.
```

- **אין שרת משלנו.** הדפדפן מדבר ישירות עם Supabase ועם Google.
- **עובד גם ברשת רעועה.** כל שינוי חל מיד, נשמר במכשיר ונכנס לתור כתיבה
  שמנסה שוב עד שהצליח. המזהים נוצרים בלקוח וכל כתיבה היא upsert, ולכן שליחה
  חוזרת אינה יוצרת כפילויות.
- **Google אינו נקודת כשל.** הטוקן שלו חי כשעה, אבל שום נתון אינו תלוי בו:
  המסמך הוא תצוגה של המסד, ונכתב מחדש כשיש חיבור.
- **בקוד אין שמות של תלמידים.** הריפו ציבורי. הנתונים במסד בלבד; הבדיקות
  רצות על כיתות בדויות (`src/engine/fixtures.ts`).

## הרצה

נדרש Node 22.

```bash
npm ci
npm run dev        # http://localhost:5173
npm test           # בדיקות הלוגיקה (TEST_SEED=<מספר> לרצף אקראי אחר)
npm run build      # בדיקת טיפוסים + בנייה ל-dist/
```

`.env` מחזיק את כתובת Supabase, המפתח הציבורי ומזהה הלקוח של Google. שלושתם
מיועדים לדפדפן ואינם סוד — ההגנה היא ה-RLS במסד.

### מסד הנתונים

```bash
SUPABASE_ACCESS_TOKEN=sbp_... npm run db:apply          # מריץ את supabase/migrations
SUPABASE_ACCESS_TOKEN=sbp_... npm run migrate:legacy    # הגירה מהמערכת הקודמת
```

המיגרציות וההגירה כתובות כך שאפשר להריץ אותן שוב. קובץ נתוני ההגירה
(`migration-data/`) מכיל שמות ולכן אינו בריפו.

משתמש חדש: יוצרים אותו ב-Supabase (Authentication → Users) ומוסיפים את המייל
לטבלת `owners`. הרשמה עצמית סגורה.

### Google Cloud — פעם אחת

בפרויקט שמחזיק את ה-OAuth Client: להפעיל **Google Drive API** ו-**Google Docs
API**, ולוודא שכתובת האתר רשומה ב-Authorized JavaScript origins.

## פרסום

Vercel בונה מ-`main`. `.github/workflows/ci.yml` מריץ בדיקות ובנייה על כל
דחיפה — בודק בלבד.

המערכת הקודמת (חלוקת הרכבים מול Google Sheets) שמורה בענף `legacy-v1`.
